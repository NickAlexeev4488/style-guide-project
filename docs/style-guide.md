# Стайлгайд документации MkDocs

## Назначение и область применения

Стайлгайд устанавливает единые правила создания и оформления документации в MkDocs. Он применяется ко всем Markdown-страницам, настройкам навигации, примерам кода, изображениям и ссылкам проекта.

## Аудитория и цель документа

Перед написанием автор определяет основного читателя и результат, который тот должен получить. Документ должен отвечать на конкретный вопрос или помогать выполнить конкретную задачу.

Если материал рассчитан на начинающего читателя, специальные термины поясняются при первом использовании. Перед инструкцией указываются необходимые права, программное обеспечение, исходное состояние системы и другие предварительные условия.

## Структура проекта

Вся документация хранится в каталоге `docs`. Главная страница называется `index.md`. Связанные материалы объединяются в тематические каталоги. Файл `mkdocs.yml` находится в корне проекта и содержит настройки сайта и навигации.

Не следует создавать несколько страниц с одинаковым назначением. Если материал становится слишком большим, его нужно разделить на самостоятельные страницы и связать относительными ссылками.

## Структура страницы

Рекомендуемый порядок разделов:

1. Название.
2. Краткое назначение.
3. Предварительные условия.
4. Последовательность действий.
5. Ожидаемый результат.
6. Проверка результата.
7. Возможные ошибки.
8. Связанные материалы.

Ненужный раздел можно исключить, но нельзя скрывать обязательное условие или способ проверки результата.

## Имена файлов

Имена файлов и каталогов пишутся латиницей, в нижнем регистре и без пробелов. Для разделения слов используется дефис.

Правильно:

```text
getting-started.md
user-guide/
error-messages.md
```

Неправильно:

```text
Getting Started.md
Руководство.md
error_messages.md
```

## Заголовки

На каждой странице используется один заголовок первого уровня. Название заголовка должно кратко отражать содержание страницы.

Уровни заголовков используются последовательно:

```markdown
# Установка

## Предварительные условия

## Порядок установки

### Установка зависимостей
```

Нельзя переходить от заголовка первого уровня сразу к заголовку третьего уровня. После заголовка должен находиться содержательный текст.

## Навигация

Все основные страницы добавляются в раздел `nav` файла `mkdocs.yml`.

```yaml
nav:
  - Главная: index.md
  - Основные правила: rules.md
  - Структура: structure.md
  - Стайлгайд: style-guide.md
  - Доступность: accessibility.md
  - Тестирование: testing.md
```

Название пункта меню должно соответствовать содержанию страницы. После добавления или переименования файла необходимо обновить навигацию.

## Язык и терминология

Текст пишется понятным и нейтральным языком. Один абзац раскрывает одну основную мысль. В инструкциях используются глаголы действия: «Откройте», «Выберите», «Введите», «Запустите», «Проверьте».

Для одного понятия используется одно утверждённое название во всех разделах. Аббревиатура расшифровывается при первом использовании, если она может быть непонятна читателю.

## Списки и таблицы

Нумерованный список используется, когда важен порядок действий. Каждый шаг должен содержать одно действие и при необходимости короткое пояснение результата.

Маркированный список применяется для равноправных вариантов, условий или характеристик. Элементы одного списка должны иметь одинаковую грамматическую форму.

Таблица используется для сравнения объектов по одинаковым признакам или для компактного представления параметров. Большие объяснения не следует помещать в ячейки таблицы.

## Команды, код и параметры

Команды и код помещаются в отдельные блоки с указанием языка:

```bash
pip install mkdocs
mkdocs serve
```

Перед блоком автор объясняет, где и зачем выполняется команда. После блока указывается ожидаемый результат или способ проверки.

Имена файлов, каталогов, функций, параметров и значений приводятся без изменения. В примерах используются безопасные тестовые данные. Настоящие пароли, токены, ключи и персональные сведения публиковать запрещено.

## Описание ошибок

Сообщение об ошибке приводится точно. После него указываются вероятная причина, способ проверки и последовательность исправления.

Нельзя ограничиваться советом «попробуйте ещё раз», если известна проверяемая причина проблемы.

## Ссылки

Для переходов между страницами используются относительные ссылки:

```markdown
Подробнее см. в [правилах доступности](accessibility.md).
```

Текст ссылки должен описывать целевой материал. Не следует использовать слова «здесь» и «по ссылке» без дополнительного пояснения.

## Изображения

Изображения хранятся в каталоге `docs/assets/images`.

```markdown
![Страница настройки проекта](assets/images/project-settings.png)
```

Изображение добавляется после первого упоминания в тексте. Оно должно показывать только нужную область, иметь читаемый масштаб и не содержать персональных данных. Значимая информация с изображения кратко дублируется текстом.

## Проверка документации

Перед отправкой изменений автор запускает локальный сервер:

```bash
mkdocs serve
```

Документация проверяется в браузере. Затем выполняется строгая сборка:

```bash
mkdocs build --strict
```

Необходимо убедиться, что страницы открываются, навигация работает, ссылки не повреждены, изображения отображаются, а сборка завершается без ошибок.

## Ревью и обновление

Перед публикацией другой участник воспроизводит основные шаги и проводит редакторскую проверку. Автор исправляет замечания или аргументированно объясняет исключение.

При изменении продукта обновляются связанные инструкции, команды, примеры и изображения. Устаревший раздел обновляется или удаляется.

## Чек-лист перед публикацией

Перед публикацией убедитесь, что:

- страница находится в каталоге `docs`;
- имя файла соответствует правилам;
- цель и аудитория понятны;
- предварительные условия указаны;
- заголовки образуют правильную иерархию;
- страница добавлена в `nav`;
- команды и шаги можно воспроизвести;
- результат можно проверить;
- ссылки и изображения работают;
- термины используются единообразно;
- типичные ошибки описаны;
- `mkdocs build --strict` выполняется без ошибок;
- изменения проверены другим участником.
