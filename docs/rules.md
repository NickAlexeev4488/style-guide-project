# Основные правила

## Хранение документации

Все страницы документации создаются в формате Markdown и хранятся в каталоге `docs`. Файл `mkdocs.yml` используется для настройки проекта, темы и навигации.

## Имена файлов

Имена файлов и каталогов пишутся латиницей, в нижнем регистре и через дефис.

Правильно:

```text
getting-started.md
user-guide/
error-messages.md
```

Неправильно:

```text
Getting Started.md
Руководство.md
error_messages.md
```

## Содержание страницы

Одна страница должна описывать одну основную тему. Большие материалы необходимо разделять на несколько связанных страниц.

На странице используется один заголовок первого уровня. Подразделы оформляются заголовками второго и третьего уровней без пропуска уровней.

## Навигация

Порядок страниц в меню фиксируется в разделе `nav` файла `mkdocs.yml`. При добавлении, перемещении или переименовании страницы навигацию необходимо обновить.

## Команды и код

Команды и программный код помещаются в отдельные блоки с указанием языка:

```bash
mkdocs serve
```

Перед командой объясняется её назначение. После команды указывается ожидаемый результат или способ проверки.

## Ссылки и изображения

Для переходов между страницами используются относительные ссылки. После перемещения или переименования файла все связанные ссылки необходимо проверить.

Изображения хранятся в каталоге `docs/assets/images`. Для изображения указывается понятное текстовое описание. На снимках экрана не должно быть персональных данных.

## Проверка

Перед публикацией запустите документацию локально:

```bash
mkdocs serve
```

Затем выполните строгую сборку:

```bash
mkdocs build --strict
```

Изменения должны пройти проверку другого участника команды.
