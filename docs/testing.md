# Тестирование стайлгайда

Стайлгайд протестирован на двух фрагментах документации: инструкции по локальному запуску приложения и описании запроса к API.

## Пример пользовательской инструкции

### Назначение 1

Запустить приложение в локальной среде и убедиться, что оно отвечает на запрос.

### Предварительные условия

- установлен Python версии 3.11 или выше;
- зависимости проекта установлены;
- терминал открыт в корневом каталоге проекта.

### Порядок действий

1. Выполните команду запуска, указанную в конфигурации проекта.
2. Дождитесь сообщения о готовности приложения принимать запросы.
3. Откройте локальный адрес приложения в браузере.

### Ожидаемый результат

Открывается главная страница без сообщения об ошибке.

### Проверка результата

Обновите страницу и убедитесь, что приложение повторно возвращает ответ.

### Возможная ошибка

Если терминал сообщает об отсутствующей зависимости, проверьте активное окружение и повторно установите зависимости из файла проекта.

## Пример описания API

### Назначение 2

Получить сведения об объекте по его идентификатору.

### Метод и адрес

```http
GET /items/{id}
```

Параметр `id` является обязательным целочисленным идентификатором объекта.

### Успешный результат

Сервер возвращает статус `200` и объект в формате JSON.

### Ошибка

Если объект не найден, сервер возвращает статус `404`. Клиент должен показать понятное сообщение и предложить проверить идентификатор.

### Проверка

Выполните запрос с существующим и несуществующим идентификатором. Сравните статус и тело ответа с описанием.

## Оценка результатов

Стайлгайд помог сохранить одинаковую последовательность блоков, отделить предварительные условия от действий и сделать результат проверяемым. В пользовательской инструкции стало ясно, что считается успешным запуском. В описании API одинаково представлены успешный и ошибочный сценарии.

Во время тестирования были уточнены два требования: обязательное описание предварительных условий и единая структура сообщения об ошибке. Эти требования включены в полный стайлгайд.

Ограничение проверки состоит в том, что использованы только два небольших фрагмента. При работе с крупной документацией правила следует уточнять по результатам ревью.
